# dorian v1.2.0 — truth-axis strength gate, import-aware binding, outside-world readiness

A feature + hardening release. **No breaking changes** — the new features are opt-in or a re-check
*trigger* widening only; the warrant format, checker grammar, exit codes, fold policy, and default
behavior are unchanged. The core stays zero-dependency.

## What changed

### Features (opt-in / additive)
- **`--strength-gate off|warn|fail`** (on `seal` and `verify`; default `off`) — the **truth-axis**
  companion to `--binding-gate`. Binding gates *when* a claim re-checks (trigger); strength gates
  *whether* its checker can falsify it (truth). `fail` refuses a seal (atomic no-write, exit 4) when a
  **load-bearing** claim is high-risk — a `behavior` claim backed only by existence/raw-text/opaque
  shell, a `quantity` claim backed only by existence, or an unbacked claim. It **never** marks a claim
  false and never touches trust state; default `off` is byte-identical to prior behavior.
- **C4 import-aware binding** — `verify`/`rebind` statically parse a `pytest:` test file (stdlib `ast`,
  read-only; no import execution, no `sys.path` mutation, no network) and add the tracked repo-local
  `.py` files it imports to the claim's watch, so an edit to the implementation a test imports re-runs
  the existing C4 checker. The checker still decides truth.

### Hardening / fixes (from independent adversarial review)
- **C5 `freshness:` no longer false-PASSes on non-date data.** It compared raw strings, so a value like
  `zzzz` sorted above any real date and PASSed `>= <date>`. It now parses ISO dates: a non-date value
  is `FAIL`, an invalid bound is `ERROR` — never a silent PASS. *(found by Codex review)*
- **C5 shell `expect: regex:` is now ReDoS-bounded** — it runs in the same spawned-worker / hard-timeout
  harness as C3 (catastrophic backtracking → `ERROR`, never a verifier hang), with a pattern-length cap.
  *(found by Codex review)*
- **C5 shell `expect: eq:` mismatch detail is bounded** — a command's observed stdout is truncated in
  the failure detail so it cannot bloat logs or leak large output through renderers. *(found by Codex review)*
- **C5 `reconcile:` sqlite read-only URI is percent-encoded** — an in-repo file whose *name* contains a
  URI query can no longer inject params that override `mode=ro`. *(found by the security-audit workflow)*
- **Sidecar/scaffold atomic writes use a per-process temp name** — two concurrent seals of the same
  artifact each promote their own private temp via `os.replace` instead of racing on one shared `.tmp`.
  *(found by the security-audit workflow)*
- **Docs honesty:** `SECURITY_BOUNDARY.md` now discloses that `--checker-source base` substitutes only
  the checker *spec* — claim selection and read-set still come from the PR-head sidecar, so a hostile
  fork's rewritten sidecar is not fully defended; base-ref selection is tracked hardening. *(found by Codex review)*

## Security notes

No change to the trust model: `dorian` is a verifier for **trusted repos**, **not a sandbox**. C4
`pytest:` and C5 `shell:` checkers execute code; `--deny-exec`/`--deny-shell` and `checker_trust: base`
fail closed (ERROR), but are trust policies, not isolation. See
[`SECURITY_BOUNDARY.md`](../SECURITY_BOUNDARY.md), which now also discloses the base-mode selection/
read-set residual for hostile forks.

## Tests / gates

Full suite green (948 tests, incl. new C5 freshness/ReDoS/output-bound regressions), ruff clean,
sdist+wheel build + isolated zero-dependency install smoke, golden path from the wheel, and an
independent Codex review + an 8-dimension adversarial security-audit workflow (0 release blockers).

## Known limitations

- Verifies explicit, checkable claims — not arbitrary correctness; not a sandbox; not an LLM judge.
- One documented, reproduced real cross-PR catch (`encode/httpx`) — not broad real-world validation.
- `--checker-source base` is a checker-spec trust root, not a complete hostile-fork defense (above).

## Upgrade notes

`pip install -U dorian-vwp`. Already-sealed warrants are unaffected; no schema, grammar, exit-code, or
fold-policy change. The new gates are opt-in (default `off`).
